# 原版 CPC 當時間最佳的參考

日期：2026-11-25
程式：`run.py`（呼叫 `third_party/rpg_time_optimal`，沒有修改）
結果：`results/out_<k>.txt`（IPOPT 的輸出，沒有跑完）

## 目的

使用者：「你先實作原版的好不好，不要拿個垃圾來比，然後花一大堆時間對齊垃圾。」要跟原版 CPC（Foehn et al., Science Robotics 2021）比，不是跟 `examples/quad_time_optimal.py` 那個簡化版比。

## 方法

- 原版的寫法：一個總時間 T，N = nodes_per_gate × 門數個 RK4 節點，每顆馬達推力在 [T_min, T_max]，|w_x|、|w_y| ≤ 15，|w_z| ≤ 0.3，z ≥ 0.5，前 35 m 推力和角速度慢慢放開（quad.yaml）。
- 過門：用進度變數 μ、λ 加上互補限制 λ(|p − g|² − τ) ≤ 0.01，讓最佳化自己決定在哪個節點過門。
- 我的設定：從最後一個門懸停起飛，7 個門飛三圈（21 個路點），沒有終點限制。圈速 = 第二圈過門 0 到第三圈過門 0 的時間。賽道 0 是 UZH 賽道，賽道 1–9 是 `track_utils.random_track(seed)`。

## 結果

- 10 條賽道平行跑了 1 小時 45 分，沒有一條收斂。例如賽道 0 跑到第 760 次迭代時，可行性誤差還有 0.63、對偶誤差 1.9×10⁶。
- 使用者決定關掉（「那把原版 CPC 關了吧」）。

## 觀察

- 原版的互補限制讓 IPOPT 非常慢。之後的比較都用已存的 CPC 解（`logs/cpc_traj_tol0.24_<k>.npz`，簡化版 CPC，過門容許誤差 0.24 m）。
- 還沒做：用更寬鬆的設定（較少節點、單圈）讓原版收斂，再跟簡化版的解比較。
