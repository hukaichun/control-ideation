# 直接在控制律的表示法裡做速度規劃（第 1 步：路徑固定）

日期：2026-11-25
程式：`pieces.py`（切段、每段擬合 f、g）、`run.py`（每段的速度 r_i(x) 最佳化）、`check.py`（最佳化前的檢查）
結果：`results/run_<k>.txt`、`results/log_<k>.txt`、`results/check.txt`

```bash
cd experiments/2026-11-25_law_pieces_speed
uv run --with casadi --with pyyaml --with scipy --with numpy python check.py
uv run --with casadi --with pyyaml --with scipy --with numpy python run.py <track>
```

## 目的

使用者：「能不能直接對 f g h 做規劃」→ 討論後：先找一條初始路線，切段寫出各段的 f、g、h，得到的還是分段參數化的曲線，
所以直接把控制律的分段曲線當規劃的表示法，規劃完就是控制律，不必再擬合第二次（「新的策略」）。
第 1 步：路徑固定，只規劃每段的速度。

## 方法

- 切段：跟混合 B-spline 控制律一樣（`../2026-11-24_blended_bspline_pieces`），每轉 45° 切一刀，核心段 ≥ 2.5 m，前後各延伸 D = 1 m 重疊；
  閉合的圈照 `fly_test.build_closed` 展開三次、在中間那份切。
- 每段：弦座標系 e1、e2、e3，路徑 q(x) = O + x e1 + f(x) e2 + g(x) e3，f、g 5 次 B-spline（節點 ≤ 0.5 m），擬合 CPC 的路徑後固定（只是測試路徑）。
- 速度（我的選擇，待使用者確認）：r_i(x) = (dx/dt)²，每段一條 4 次 B-spline（節點 ≤ 1 m）。控制律的 h 由它精確算出：h_i = −½ r_i (1 + f′² + g′²)。
- 目標：T = Σ ∫_核心 dx / √r_i，每個節點區間 8 點 Gauss。
- 限制：每段核心上的取樣點（每 0.125 m 加所有節點），四條物理限制和 `../2026-11-25_two_formulations` 相同（不管機頭）。
- 接點（我的選擇，待使用者確認）：每個切點上，兩段的 v² 和它沿弧長的一、二、三階導數相等（速度、加速度、jerk、snap 沿路徑連續）。
  重疊區其餘部分不加限制，只量兩段的速度差。
- 起點 2 m/s，IPOPT。

## 最佳化前的檢查（`results/check.txt`）

- 切段：賽道 0、1、4、7、8、9 成功（8–16 段，路徑擬合 0.15–3.8 mm，切線和弦的最大夾角 37–75°）。
  **賽道 2、3、5、6 切段失敗**：急彎讓一段延伸後轉超過 90°，在弦座標上不再是單調的，圖形形式 y = f(x) 寫不出來。
- 每段的幾何導數 q_x..q_xxxx 對有限差分：10⁻⁵。
- 接點的 v² 和三階弧長導數對沿弧長的多項式擬合：一致到小數 4 位。

## 把重疊區放進問題（使用者：「重疊區速度差那麼高看起來就不可能」）

- 確認原因：每段核心裡的速度正常，但重疊區的末端有幾段衝到 300–400 m/s（賽道 0：第 1、3、4、6、13 段）。重疊區不在目標也不在限制裡，所以被放任。
- 修改（`run.py`，預設 `OVL=1`）：
  1. 限制在每段的整段上檢查（含重疊）；
  2. 重疊區每 0.1 m，兩段的 v² 相差不超過 EPS = 1 m²/s²（10 m/s 時約 0.05 m/s；v² 對 r 是線性的，所以是線性限制）。

  - f、g 多擬合 0.5 m（尾端不在使用範圍內）：賽道 1、4、7、8 回到 +1.6–5.2%；但賽道 9 有一段弦很斜（切線和弦夾角 67°），加寬後擬合誤差變 90 mm；賽道 0 加寬後轉超過 90°，切段失敗。
- 40 倍網格上的扭矩倍率：賽道 0、9 到 2.5–3.0（取樣點上 1.000），還沒查是在哪裡。

## 可用性：規劃結果直接當控制律飛（`fly.py`，`check_law.py`）

- 每段規劃好的 f、g、r 直接就是控制律的一段：φ = (e2·q − f(x), e3·q − g(x))，V = h = −½ r (1 + f′² + g′²)，不再擬合。
  混合、增益、模擬器都跟 `../2026-11-24_time_optimal_in_our_space/fly_test.py` 相同（完整機體模型、mode B、量測加速度、沒有擾動、機頭不管）。

## 拋物線 toy：切成兩段的代價（`toy_parabola.py`，使用者：「找一個拋物線型的路線，然後截成兩段，跑我們的最佳化看看」）

水平的 U 形彎 y = 0.2 x²、x ∈ [−6, 6]（頂點半徑 2.5 m），起點、終點速度 3 m/s，在頂點切成兩段，前後各延伸 1 m。
「x 軸座標系」：兩段都用世界 x 軸當弦方向，拋物線被 5 次 spline 精確表示（擬合誤差 10⁻¹⁴、曲率誤差 10⁻¹²）。
「弦座標系」：照控制律的規則，每段用自己的弦方向，旋轉後的拋物線要擬合（0.22 mm、曲率誤差 0.022 1/m）。
其他限制跟賽道上完全一樣（尾端也檢查、重疊區速度一致、切點三階導數連續）。

| 變體 | 速度節點 1 m | 速度節點 0.25 m |
|---|---|---|
| 1 段 | 1.8398 s，34 it | 1.8260 s（3000 it 沒收斂） |
| 2 段，x 軸座標系 | 1.8399 s，150 it | 1.8258 s，2109 it |
| 2 段，弦座標系 | **2.6735 s（+45%）**，30 it | 1.8290 s（+0.2%），175 it |
| 2 段，x 軸座標系，只在核心放限制 | 1.8399 s，60 it | 1.8261 s（沒收斂） |

- **切成兩段本身不花代價**：路徑精確時，切成兩段（含尾端限制、重疊一致、切點連續）跟一段一模一樣。
- **代價來自弦座標系 × 速度節點**：每段用自己的弦當 x 軸時，靠近頂點那頭的路徑對弦很斜，同樣 1 m 的 x 對應更長的路，
  而 v² = r (1 + f′² + g′²) 裡的 (1 + f′²) 變化很快，r 的 spline 跟不上，只好減速。節點 0.25 m 時差距幾乎消失（+0.2%）。
- 即使一段、路徑精確，節點 1 m 時也有 43% 的時間沒有任何限制頂住；0.25 m 時降到 19%。速度 spline 的解析度本來就是一部分代價。

## 弦座標系 +45% 的原因：我加的切點導數相等（使用者：「感覺不太對，切成四段應該可以分成急加速跟急減速各兩段，就充分了，剩下的問題就是速度 spline 是不是能貼著最佳的速度」）

- 速度曲線（`results/toy_parabola_speed.png`）：弦座標系的解在頂點附近降到 2.5 m/s，總推力只有 10 m/s²，沒有任何物理限制頂住。
- 逐條拿掉（拋物線、2 段、弦座標系、速度節點 1 m）：全部 2.6735 s；拿掉重疊區速度一致 1.9107 s；**拿掉切點的 v² 三階導數相等 1.8409 s**（= 1 段的 1.8398）；兩個都拿掉 1.8370 s。
  兩段在弦座標系下各自擬合，路徑的高階導數在切點不完全一樣，再要求 v² 的三階弧長導數兩邊相等，加上重疊區速度一致，可行的速度就被鎖死。這條是我加的，重疊區的混合本來就會處理接點。
- 賽道上拿掉這條（`JUNC=0`，`results/run_<k>_nojunc.txt`）：0 +2.0%（原 +3.1%）、1 +3.1%（+3.4%）、4 +7.6%（+8.2%）、7 +8.4% 沒收斂（+4.6%）、8 +13.3%（+14.7%）、9 +9.4%（+20.3%）。

## 不用 CasADi：JAX + 自己的 SQP（使用者：「你還是不要用 CasADi 好了」，最佳化器選「自己寫」）

- `jprob.py`：問題用 JAX 寫，每塊限制（一段、相鄰兩段、一段 + 門）一個小函數，Jacobian 用 `jax.jacfwd`，λ·g 的 Hessian 用 `jax.hessian`，都是逐塊算。
- `sqp.py`：信賴區域 SQP。QP 用 Clarabel（OSQP 每步都跑滿 20000 次、解不準，換掉）；H = 目標 Hessian + 限制曲率（上一步的乘子），特徵值截到正；
  QP 加鬆弛變數保證可解；ℓ1 merit 的實際 / 預測下降比決定接受；被拒絕時做 second-order correction（沒做時好步一直被拒，信賴區域縮到 10⁻⁴）。
- 之前 CasADi 版本慢的原因：SX 把整張圖展開，路徑變數加進來後每段的 Hessian 從 1.5 萬節點長到 57 萬（38 倍）。
- 賽道 1、路徑固定、從 2 m/s 出發（`run_sqp.py`）：105 步、67 s 到 4.04 s（IPOPT 0.4 s 到 3.853 s），還在下降。

## 速率 × 切線的寫法：繞圓柱過彎（`toy_cylinder.py`，使用者：「之前不就說過速度分成速率跟切線，切線應該就是軌跡的參數化」「用拋物線當初始，當作繞圓柱過彎的 time optimal」）

- 之前的速度變數 r = (dx/dt)² 混了路徑斜率，是我沒照設計。改成速率 Q = v² = −2h（直接就是控制律的 h），和 f、g 同一組節點；
  (dx/dt)² = Q / (1 + f′² + g′²)，導數用商的微分（`check_cyl.py`：和 JAX 一致到 6 位）。目標 T = Σ ∫ √(1 + f′² + g′²) / √Q dx（弧長 / 速率；起點檢查：等於核心弧長 / 3 m/s）。
- 題目：初始路徑 y = 0.2 x²、x ∈ [−6, 6]、z = 2 m；圓柱軸 (0, 2.5)、半徑 1 m，每個取樣點離軸 ≥ 1 m；起終點固定、速度 3 m/s。節點 ADAPT（KMAX 2 m、FTOL 1 cm）。

## 重寫：`lawplan.py` + `sqp2.py`（使用者：「限制式也太多條了」「你有辦法自己把最佳化寫優雅嗎」「接起來應該是限制」）

- 舊的多段寫錯（`toy_cylinder.py`，量過）：重疊區「同一條曲線」用起點附近的 Taylor 展開比，路徑一動就不準，實際尾端和鄰段核心差到 13 cm（最佳化器以為 10⁻⁹）；
  也沒有要求加速度一致，切點上總推力跳 20 m/s²。
- 新寫法：
  - 變數：每段 f、g、Q = v²（同一組粗節點）；加上每個切點兩邊的弦座標 x*（兩個都要是變數：只固定時，兩段各自只能沿自己的法線移動，
    交點被釘死，第一版就是這樣，路徑完全動不了）。x* 限制在起始所在的節點區間內（區間多項式精確）。
  - 目標：Σ ∫_核心 √(1+f′²+g′²)/√Q dx，核心端點是 x* 時，那個區間的 Gauss 點跟著 x* 移動。
  - 限制只有三類：物理限制（每個節點區間取節點 + 3 個內點，整段含尾端）；切點上位置、速度、加速度、jerk 相等（12 條）；任務條件（起終點、圓柱）。
  - SQP：QP 用 Clarabel；Lagrangian 的精確 Hessian（JAX）、特徵值截正；變數尺度（路徑 1 m、Q 100 m²/s²）；filter line search + 一次 second-order correction；
    line search 把步長砍到 < 0.1 時加阻尼 μI（全步時 μ/10）。
- 檢查（`check_lawplan.py`）：切點的速度、加速度、jerk 對沿時間的有限差分一致；Jacobian 2×10⁻⁹、Lagrangian Hessian 5×10⁻⁹。

|---|---|---|---|---|---|

## 兩段為什麼離最佳那麼遠（使用者：「分析一下兩段的，他離 optimal 那麼遠不正常」）

- 兩個切點座標都頂在我加的上下限：第 0 段只能在 [8.90, 9.40]、第 1 段 [0.49, 0.99]（起始節點區間；頂點附近擬合加密到 0.5 m，區間很窄）。
  1 段最佳解的頂點在這兩段的弦座標是 8.27 和 1.62，在允許範圍外。原因是我為了讓「起點附近的多項式」精確而限制切點不能離開那個區間。
- 修正：任意 x 上的 spline 值改成「找到 x 所在的區間，用那個區間的多項式」（`eval_at`，每段都精確）；時間改成 F(終點) − F(起點)，
  F(x) = 前面完整區間的積分 + x 所在區間從左節點到 x 的積分（`F_time`）。切點座標可以在整段內移動。
- 結果：2 段 1.6075 s（1 段 1.6060 s），切點移到 8.266、1.623（1 段最佳頂點 8.273、1.616）。
  但最後 line search 失敗、沒有完全收斂：剩下違反最大 3.6×10⁻³（切點 jerk，m/s³）和 2.6×10⁻³ N（馬達上限）。152 步、17.6 s。
- 4 段：1.6041 s，200 步、38 s，違反 7.8×10⁻⁵。

## 信賴區域 filter SQP（`sqp_tr.py`）

- 每步：QP 加上 |d|∞ ≤ Δ（縮放後的變數）；QP 無解時做 restoration（信賴區內最小化線性化違反量）；filter 接受準則（f-type：預測下降 ≥ 違反量²，要求實際下降 ≥ 0.1 倍預測；
  其他步驟違反量要下降並進 filter）；被拒絕時一次 second-order correction；接受且碰到邊界 Δ×2，拒絕 Δ/2。
- 第一版用固定門檻 10⁻⁴ 判斷 f-type、沒有 second-order correction：1 段 300 步停在 1.6215，2、4 段 4.73、3.43（Δ 一直被減半）。補上這兩個標準做法後：

|---|---|---|---|---|---|---|
