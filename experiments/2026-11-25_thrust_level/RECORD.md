# 參數化到推力層級，限制不除以總推力

日期：2026-11-25
程式：`bez.py`（B-spline 轉 Bézier、乘法、升階、推力錐的控制點）、`toy.py`（垂直爬升，w = dt/du）、`limits.py`（限制式）、
`check_limits.py` / `check_nh.py`（最佳化前的檢查）、`fixed_path.py`（有機頭角 ψ 的版本）、`fixed_path_nh.py`（不管機頭的版本）
結果：`results/`（`toy.txt`、`check_limits.txt`、`run_ipopt_0*.txt`、`fixed_ipopt*`、`nh_0.npy`）

## 目的

使用者：「我們寫下軌跡 p，接著要找出 dp/dt，而 p 本身就被 spline 參數化，所以 dp/dt 也是被 spline 參數化」「所以四個螺旋槳推力也被參數化」「同時注意寫出來的形式要避開 /0」。檢查過之後才開始跑最佳化。

## 方法與結果（依時間順序）

1. **toy：垂直爬升 10 m，w = dt/du**（`toy.py`）。T = ∫w du 是線性而且精確的；推力錐用 Bézier 控制點表示（凸包保證整段都在錐內）。
   - 結果：4 段 +54.7%、16 段 +10.9%、64 段 +1.4%（解析解 1.5703 s）。用控制點包住整段很保守，收斂得慢。
2. **限制式不除以總推力，機頭用水平角 ψ**（`limits.build`）：14 條限制（4 顆馬達上下限、|w_x|、|w_y|、|w_z|），全部乘開。分母一路疊到 c⁷n⁵，再乘縮放常數 1/(T_max·20⁷·20⁵)。
   - 檢查（`results/check_limits.txt`）：CPC 賽道 0 的馬達推力誤差 0.29 N；梯度正確。
   - **檢查已經露出問題，當時沒發現**：c = 10⁻³ 而側向 jerk 需要 w = 100 rad/s 的情況，限制值只有 −1.7×10⁻²¹，判成「沒有違規」。乘開後的高次方加上縮放常數，讓推力小的地方的違規看不見。
3. **固定路徑 + 機頭當變數，IPOPT**（`fixed_path.py`）：賽道 0 得到 7.47 s（+21%），而且 4 倍細網格違規。
   - 加上整圈的偏航繞圈數（CPC 每圈 −2π，WIND = −1、0、1）：10.61 s、7.47 s、8.26 s，都不對，繞圈不是原因。
   - 水平角 ψ 表示不了 CPC 的姿態（擬合誤差 89°）：CPC 會側翻到機身 y 軸接近垂直。
4. **自己的梯度投影最佳化器**（已刪除，user：「清掉你舊的演算法」）：賽道 0 每步 7.5 s，25 步後停在 20.6 s，步長縮到 10⁻¹⁴ 也找不到可接受的步。
5. **不管機頭**（`limits.build_noheading`、`fixed_path_nh.py`，user：「先把機頭拿掉」）：w_z = 0，對任何機頭都成立的限制（|w| ≤ 15，馬達取最壞機頭）。
   - 乘開 + 縮放常數：IPOPT 6.376 s（+3.3%），但**取樣點上就已經違規**：扭矩超過上限 60 倍，縮放後只剩 −10⁻⁸。取樣點之間總推力掉到 0.3 m/s²、角速度到 238 rad/s。
   - 用範數、不平方、不縮放：沒收斂，停在 9.57 s（範數在零有尖點）。
   - 平方、不縮放：沒收斂，停在 12.03 s（值從 1 到 10¹³）。

## 觀察（使用者的指正）

1. 「為什麼會需要縮放來限制推力 > 0，這用講的都覺得奇怪」：推力 ≥ 0 本來就成立，不需要那條限制；縮放是平方和乘開帶出來的，把違規藏起來。
2. 「我覺得你還是從整個最佳化目標函數跟限制式開始處理好了」：重寫成兩個乾淨的版本，在 `../2026-11-25_two_formulations`。最後改成直接用物理量（rad/s、N），就收斂了。
